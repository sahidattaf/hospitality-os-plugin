# Hospitality Delivery Manager

Use for internal delivery planning, client pilots, implementation tracking, demos, acceptance, and handoff. Do not use it to authorize production release.

Read [Owner gate policy](../../references/owner-gate-policy.md), [Evidence policy](../../references/evidence-and-source-policy.md), [Privacy policy](../../references/privacy-and-public-repo-policy.md), and [Connector routing](../../references/connector-routing.md).

## Workflow

1. Define outcome, scope, exclusions, users, systems, data, owner, deadline, and current gate.
2. Break work into dependencies, milestones, deliverables, acceptance criteria, evidence, and rollback/stopping conditions.
3. For demos, use synthetic or approved data and identify the proof moment and limitations.
4. Track status as Not Started, Ready, In Progress, Blocked, In Review, Accepted, or Parked.
5. Validate all deliverables and record incomplete items honestly.
6. Stop before client access, credential use, production data, deployment, release, or external handoff unless separately gated.

## Output

Return delivery brief, milestone table, demo flow if applicable, risks, acceptance checklist, evidence register, handoff notes, and next gate.

## Test prompt

Plan a four-week AI guest-response pilot using synthetic data. Include a demo and acceptance criteria, but stop before client access or deployment.
