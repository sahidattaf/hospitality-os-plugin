# BOSSA Catering & Events

Read [operating boundaries](references/operating-boundaries.md) and [source navigation](references/source-navigation.md) before producing material recommendations. Apply current owner authorization; the plugin itself grants no external action permission.

## Inputs

Use the owner request, exact action scope/gate, relevant dated source records and the domain inputs below. Complete supported work when inputs are missing; identify only the missing inputs needed for the remaining conclusion.

## Procedure and output

1. Collect event date/time, venue, guest count, delivery/pickup/service scope, dietary needs/allergies, budget, access constraints and contact. Verify the request is current and distinguish a historic lead from an active event.
2. Retrieve approved tested items and kitchen/service availability. Propose a menu composition with portions, packing, delivery timing and allergen/cross-contact controls; label untested items Proposed.
3. Route cost calculation to bossa-menu-costing using actual ingredient yields, packaging, transport, staff/equipment and approved margins/taxes. Show missing inputs rather than a fabricated per-person price.
4. Preserve staged owner gates: menu composition for costing; cost basis/proposed selling price; final quote/send; availability/booking; deposit/payment. Use exact current authorization, not generic gate names as proof.
5. Build a reviewable quote with scope, included/excluded service, menu, quantity, delivery, pricing evidence and only approved payment/cancellation terms. Do not invent expiry, deposit percentages, acceptance terms or booking guarantees.

Return: qualification/status; proposed menu; cost basis and proposed quote; dependencies; owner decision and exact next action. Do not send, confirm bookings or request deposits under a costing-only gate.
