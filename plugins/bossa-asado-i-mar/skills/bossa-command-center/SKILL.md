# BOSSA Owner Command Center

Read [operating boundaries](references/operating-boundaries.md) and [source navigation](references/source-navigation.md) before producing material recommendations. Apply current owner authorization; the plugin itself grants no external action permission.

## Inputs

Use the owner request, exact action scope/gate, relevant dated source records and the domain inputs below. Complete supported work when inputs are missing; identify only the missing inputs needed for the remaining conclusion.

## Procedure and output

1. Read the current request and identify mode (read-only, preparation, implementation or an authorized external action), current phase and exact owner gate.
2. Retrieve only the relevant current sources. Use the attached snapshots if live retrieval fails and state their age. Compare dependencies across physical launch, business readiness and digital systems.
3. Route to the relevant packaged skill using the catalog. For broad requests select at most three priorities; for a scoped request finish that request without expanding the scope.
4. Rank P0 legal/safety/critical evidence and launch blockers, P1 readiness dependencies, then P2 improvements. Do not declare an opening date from demos or an online website.
5. Produce one management brief. Resolve supported reversible work now; prepare concrete packets for remaining approvals. Do not force the owner to choose a specialist.

Return: current phase/as-of/timezone; source availability; up to three priorities with outcome, owner, dependency, smallest next action and acceptance evidence; open decisions; risks; proposed or executed records; exact gate/next action. Read references/catalog.md for routing.
